# SK 하이닉스 AI 기반 문제 해결 경험 기술서

---

## 경험 요약

- **[기간]** 2026.08
- **[경험]** AI 에이전트 기반 반도체 BG(Back Grinding) 공정 불량 원인 자동 규명 및 최적화 방향 도출
- **[역할]** 공정 데이터 분석 설계, AI 에이전트 지시(Prompt Engineering), 결과 검증 및 물리적 해석, 보고서 구성 총괄

---

## 1. 문제 상황 및 AI 활용 배경

- **공정 현황:** BG(Back Grinding) 공정 이후 발생하는 대규모 불량 (Crack 초과 4,015장/20.1%, TTV 규격 이탈 4,964장/24.8%)으로 최종 수율이 극도로 저하된 상황
- **기존 방식의 한계:**
  - 현장 엔지니어 경험에만 의존한 주관적 원인 추정 → 부서 간 책임 전가 및 소모적 논쟁 반복
  - 잘못된 방향의 개선 실험(Fine Grinding DOE) 시도 → 시간·비용 낭비
  - 2만 건의 다변량 공정 데이터에서 비선형적 복합 인과관계를 수작업으로 밝혀내는 것은 현실적으로 불가능
- **AI 도입 이유:** 대용량 센서·계측 데이터에서 복수 변수 간의 비선형 상호작용을 정량적으로 규명하고, 물리적 해석 및 엔지니어링 판단의 객관적 근거를 확보하기 위함

---

## 2. AI 활용 방법 (무엇을, 어떻게 지시했나)

### ① 데이터 전처리 및 탐색적 분석 설계

- AI 에이전트에게 20,000건 엑셀 데이터의 결측치 처리, 이상값(Outlier) 탐지, 공정 변수별 기술통계 요약을 자연어로 지시 → 수작업 대비 **분석 준비 시간 약 80% 단축**
- **VIF(분산팽창계수) 다중공선성 검증**을 AI가 자동 수행 → 모든 변수 VIF < 5 확인, 이후 머신러닝 결과의 통계적 신뢰성 확보

### ② 머신러닝 파이프라인 자동 구축

- Random Forest 분류 모델을 AI에게 지시하여 학습 → **불량 예측 정확도 확보 + 변수 중요도(Feature Importance) 자동 추출**
- 불균형 데이터(Pass 17% : Fail 83%) 보정을 위한 `class_weight='balanced'` 적용을 AI가 자동 판단·설정
- **핵심 도출 결과:** 공정 불량의 **89%가 입고 TTV(웨이퍼 평탄도 불량)에서 기인**함을 정량 수치로 확인
  - 기존 현장의 추정("Fine Grinding 연삭 부족")을 데이터로 완전히 폐기하는 결정적 근거

### ③ 통계적 공정 능력 진단 (Cpk 자동 산출)

- TTV는 망소특성(Smaller-is-Better)으로 LSL(하한선)이 없는 **단측 규격 Cpk 공식** 적용을 AI와 함께 설계
  - $C_{pu} = \dfrac{USL - \mu}{3\sigma}$
- 산출 결과: **Cpk = 0.15** (최소 합격선 1.33 대비 극도로 미달, 통제 불능 상태 수학적 확인)

### ④ 단계적 Red Team 검증 루프 (AI의 양면 활용)

- 분석 결과 도출 시마다 AI에게 **"지금 분석의 논리적 허점을 공격적으로 비판하라"** 는 Red Team 역할을 부여하여 주장의 완결성 검증
- **사전 차단한 핵심 반론 5개:**
  - "VIF 검증이 충분한가?" → 전 변수 VIF < 5 입증으로 반박
  - "Crack이 아니라 Fine Grinding 부족 탓 아닌가?" → KDE 분포 분석에서 Scratch 크게 감소(2.93→1.24)했으나 Crack은 악화됨 확인으로 반박
  - "모델 과적합 아닌가?" → 불균형 클래스 보정 및 Gini Importance 기반 해석으로 반박
  - "TTV NG 중 Pass 웨이퍼가 있지 않나?" → 전체 0.2%(8장)만 생존, 99.8% 폐기 확인으로 반박
  - "LSL 없이 Cpk 산출이 가능한가?" → 망소특성 단측 규격 수식 적용 근거 제시로 반박

### ⑤ 자동 시각화 및 단일 리포트 패키징

- AI 에이전트가 총 **7종 고해상도 차트(PNG) 자동 생성** 및 단일 HTML 분석 리포트로 자동 패키징
  - Cpk 히스토그램 / RF Feature Importance / Crack·Scratch·TTV KDE 밀도 함수 / 시계열 드리프트 / TTV-Crack 산점도 / 피어슨 상관계수 히트맵 / 4M1E 특성요인도(Fishbone)
- 상관계수 히트맵에서 **TTV_After ↔ Crack_After 피어슨 r = 0.694** 확인 → 두 불량이 동일한 근본 원인을 공유함을 시각적으로 증명
- 보고서 작성 소요 시간: 기존 수작업(2~3일) 대비 **당일 자동 생성(70~80% 단축)**

## 3. AI가 아니면 불가능했던 핵심 발견

| 발견 사항 | 물리적 해석 |
|---|---|
| 입고 TTV → 불량 기여도 89% | 앞 공정 유입 '휜 웨이퍼'가 모든 BG 불량의 근원 |
| TTV-Crack 상관계수 0.694 | 두 불량은 독립적이지 않으며 Rough Grinding 과부하라는 단일 원인 공유 |
| Scratch 감소(2.93→1.24) vs Crack 악화 | Fine Grinding은 정상 작동 중, 문제는 초기 충격(SSD)에 있음 |
| Cpk 0.15 (통제 불능) | 정상/불량 웨이퍼 무관 획일적 가공 압력 인가가 원인 |

**결론:** Preston 방정식($MRR = k \cdot P \cdot V$)에 의거, **입고 TTV 편차에 연동하여 Rough Grinding의 압력(P)과 속도(V)를 자동 하향 조절하는 Feed-Forward 제어 로직 수립**이 프로젝트의 궁극적 방향으로 도출됨

## 5. 결론 및 향후 적용 가능성

- 본 경험을 통해 **AI 에이전트는 단순 질의응답 도구가 아니라, 분석 설계 → 모델링 → 검증 → 보고서 생성까지 이어지는 엔지니어링 파이프라인 전체를 협업으로 수행할 수 있는 파트너**임을 직접 증명
- SK 하이닉스의 실제 공정 데이터(SAW, CMP, Etch 등)에도 동일한 방법론을 적용하면, **현장 엔지니어가 AI와 반복적 검증 루프를 구성함으로써 수율 저하 원인을 훨씬 빠르고 객관적으로 규명**할 수 있을 것으로 확신
- 궁극적으로 AI 분석 결과를 실시간 설비 제어 로직(Feed-Forward)으로 연결하는 **Closed-Loop 스마트 팩토리 구현**에 기여하고자 함
